# PDF-OS-CR Repository Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the working research snapshot into a clean, documented public repository without changing its model behavior, root commands, data conventions, or checkpoint format.

**Architecture:** Keep `train.py` and `test.py` as stable entry points, centralize duplicated dataset behavior behind a small registry, group model files by paper component, and resolve repository-owned paths from the repository root. Preserve every state-dict-sensitive module attribute while replacing personal paths and generated clutter with documented configuration.

**Tech Stack:** Python, PyTorch 1.9.1 (paper environment), Rasterio, NumPy, SciPy, OpenCV, scikit-image, timm, pytorch-msssim, LPIPS, TensorBoardX, Matplotlib, THOP, pypardiso.

**Spec:** `docs/superpowers/specs/2026-10-08-repository-refactor-design.md`

## Global Constraints

- Preserve `python train.py` and `python test.py`.
- Preserve the two existing `ckpt/<dataset>/best_model.pt` files and their state-dict compatibility.
- Do not change network layer definitions, registered module attribute names, loss weights, tensor channel ordering, normalization constants, dataset split interpretation, or manuscript result values.
- Do not run tests, training, evaluation, inference, model profiling, or benchmarks.
- Verification is static only: inspect files, imports, paths, checkpoint-sensitive names, image crops, and Markdown links.
- The repository has no Git metadata, so do not create commits or claim Git history.
